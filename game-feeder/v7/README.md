# 接駁巴士 v7 · 模組版（五個模式）

> 給組員和接手的 AI 看的：v7 的檔案怎樣分、怎樣加一個新模式、怎樣打包和測試。玩法方案見 `docs/for-codex/2026-10-13-五模式与AI生成关卡.md`。

## 為什麼要分模組

每個模式是一個**獨立的頁面、獨立的引擎、獨立的打包檔**。改一個模式不會影響其他模式；只有外觀（顏色、字體、像素圖示、頂欄、卡片、提示框）和語言工具放在 `shared/` 共用，以後統一改 UI 只改一處。最後由入口頁（之後換成全港波點地圖、點進去波點飛成棋盤）把各模式串起來；組員也可以把自己的東西掛到入口上。

## 怎樣玩 / 打包 / 測試

- 玩：雙擊 `开始.html`（入口）或 `mode1-bus/模式1-车站与步行.html`。
- 打包：`python game-feeder/v7/build.py`（改了任何源檔、包括 `shared/`，都要重新打包）。
- 測試：`node game-feeder/v7/mode1-bus/test_engine.js`（約 5 分鐘）。
- 截圖 / 指定局面：網址後加 `#map=l2&intro=0&tips=0&layout=0-7-11&t=400`（`intro=0` 不彈開場卡，`tips=0` 不出提示）。

## 加一個新模式

1. 新建 `modeN-名字/`，頁面引用 `../shared/style.css`、`../shared/i18n.js`、自己的 `strings.js`、需要的話 `../shared/tips.js`。
2. 引擎、關卡、文字都放在自己的資料夾裡，不要改別的模式的檔案；需要共用的東西先放進 `shared/`，並在這份說明裡寫一句。
3. 寫自己的 `build.py`（照 `mode1-bus/build.py`），`v7/build.py` 會自動找到它。
4. 在入口頁 `index.html` 把那張卡從「設計中」改成連結。

## 模式 2 · 地鐵（一次建好，看它長大）的規則

想法：地鐵改變的不只是「怎麼去」，更是「去哪裡」——一個地方變近了，原來不去的人也會去；而新線要靠口耳相傳慢慢被發現。全部按「格」數，五條規則：

1. **去哪裡＝吸引力 − 要走幾格**（開車、走路、地鐵取最快的）。元朗市中心 24、洪水橋新發展區 22，「附近」固定 10；每個屋苑的人按這幾個數的比例分。
2. **怎麼去：比開車或走路（取快的）省幾格，就有幾成人坐地鐵**（最多 10 成）。走路很慢，每格算 2：直接走過去＝相隔格數 × 2；坐地鐵＝走到站（每格 2）＋ 等車 2 ＋ 路過幾個站 ＋ 走到目的地（每格 2）；開車＝相隔格數 ＋ 泊車（元朗 3、洪水橋 7：新區路未通、車位少）。
   - **順路再去**：到了一個目的地的人，按同樣的兩條規則決定要不要再去另一個——拉力＝另一個的吸引力 − 兩地之間要幾格，和「辦完就回家」（固定 40）按比例分；省幾格就有幾成坐地鐵。所以兩個中心之間每天也有人來回，一條線把它們連起來，這一段也會很多人坐。 只有知道地鐵的人才會因為地鐵多去、改坐地鐵。
3. **只有知道地鐵的人才按 1、2 選**；不知道的人照舊開車或走路去老地方。開通時每個屋苑 2 成人知道。
4. **口耳相傳**：一個屋苑今年有幾成人坐地鐵，明年「還不知道的人」裡就有（幾成 × 2）聽說了。
5. **擠**：每段線每天最多載「列車數 × 40」人；明年經過太擠的段的行程多算 4 格（只算一次）。

第 0 年在 14×9 棋盤上畫一條線（可拐彎、不分叉）、放站、買列車，預算 40（線每格 1、站 3、多一列車 4）；**開通後八年都不能改**，可以「回到規劃」重來。分數＝八年每年「每天坐地鐵的人」加起來。門檻 550 / 760 / 900（`bots/v7_metro_grow.js`：最好 969——元朗→洪水橋→往下到天瑞邨，4 站、3 列車、從來不擠，元朗每天來的人 105→131、洪水橋 93→126；局部最優 p90 約 690、中位約 260；直線 天耀邨→洪水橋→元朗 三站：1 列車 473（擠）、2 列車 636；只連兩個中心 289——沒有屋苑在線上，口碑傳得慢）。

**AI 示範（臨時）**：左上「AI 示範」選過關 / 高分 / 大師，AI 在棋盤上一步一步建它的方案（畫線、逐個放站並說明接誰、買車並說明最擠一段的人數、這一套的想法），然後開通播放八年。方案由 `node bots/v7_metro_grow.js 600 '{}' --write` 寫進 `mode2-metro/demo-plans.js`（過關、高分挑「從不擠、沒有相鄰兩站」裡站和車最少的方案）。拿掉時刪 `demo.js`、`demo-plans.js` 和 `index.html`、`build.py` 裡標著 AI demo 的地方。

之前的版本：靜態 b36f747、經營六年（經驗常數） befc757、看它長大第一版 cc3e9c2（還沒有走路，預算 30）、加走路與 AI 示範 c776853（還沒有順路再去）。

## 模式 3 · 路會塞（九龍東）的規則

想法：第二關的地鐵放到真實地圖上，加上路和已有的地鐵。新線把人從路上帶走，路就通；可是路一通，開車又變好走，有人回去開車（誘發交通 / Downs–Thomson）。開車的人是**慢慢學**的，所以塞車會先降、後回升一點，最後停在中間。

- **地圖**：九龍東 14×12 格，一格約 600 米（HK1980 坐標：格 = (x − 837,500, 823,500 − y) ÷ 600）。屋苑、商貿區的位置、人口、岗位取自 `data/model/zone-centres.parquet` 和 `data/web/zones-2026.geojson`（觀塘站一帶 151,391 個岗位、九龍灣站一帶 86,552；啟德 84,141 人、2026 比 2021 +180%；秀茂坪一帶 +21%）；路的選擇參考早高峰分配 `assignment-am-2026.parquet` 裡最塞的路（觀塘繞道 v/c 1.57、清水灣道 2.35、將藍公路 1.52 等）。遊戲數字是縮放後的示意（D 級，僅供學習）。情景：十多年後啟德住滿、安達臣道入伙、寫字樓再多一半；路已經塞，地鐵還沒跟上。
- **第二關的規則照用**：拉力 = 吸引力 − 格數（對「附近」10）；省幾格幾成坐地鐵；順路再去（對「辦完就回家」40）；只有知道新線的人用它（開通 2 成，口耳相傳 ×2）。這裡一格 600 米，走路每格算 3。
- **走路**：不坐地鐵的人裡，走路比開車省幾格，就有幾成走路（漸變，避免一下子全部轉）。
- **已有的地鐵**：觀塘綫（彩虹→油塘）、將軍澳綫（油塘→寶琳），大家都知道；換綫 = 走過去 + 再等一次車。新線的站在舊綫的站上或旁邊一格就能換。
- **路會塞**：開車從屋苑開上最近的路（1 格以內），沿路走（每段 1 格），開下來到目的地，加泊車（觀塘 4、九龍灣 3）；路線固定（最短）。每段多花 (車 ÷ 容量)² 格；塞車 = Σ 每段的車 × 多花的格數。
- **開車的人慢慢學**：今年以為的塞車 = 去年以為的 + 0.3 × (去年真的 − 去年以為的)。地鐵太擠也一樣慢慢學（最多 4 格，一趟算最擠的一段）。「什麼都不做」先讓路況學到穩定（977）。
- **分數**：每年「什麼都不做」的塞車 − 你的塞車，八年加起來（車·格）。門檻 1500 / 2600 / 3600（`bots/v7_roads.js`：最好 4207——寶琳→秀茂坪→觀塘商貿→九龍灣商貿，4 站 2 車，塞車 977 → 最低約 250、之後回升到 400–500；局部最優 p90 約 2480、中位約 1190）。AI 示範：過關 1631（秀茂坪接到觀塘站換綫）、高分 2618（啟德→九龍灣→觀塘站）、大師 4207。

## 模式 4 · 地面巴士的規則

想法：地鐵是「一次建好、很難改」的長期決定；巴士相反——便宜、靈活、**每年都可以改**，可是走在路上，路塞它也塞。巴士專線讓它不塞，車卻少了一截路。地圖、畫面、規則都接著第三關，玩家一進來就有手感。

- **地圖**：第三關的九龍東，幾年以後——第三關的東九龍綫（AI 大師那條：寶琳→秀茂坪→觀塘商貿→九龍灣商貿，3 列車）已通車；啟德、安達臣道住滿（人約多一半）；商貿區泊車更貴（觀塘 6、九龍灣 5）。
- **巴士線**（最多 3 條 A/B/C）：沿路畫（只能走在路上），線上放站，加巴士才開。坐巴士 = 走到站（每格 3）+ 等車（6 ÷ 巴士數）+ 每段路（1 + 大家以為的塞車）+ 每停一站 1 + 走過去；站在地鐵站上或旁邊能換乘。每條線每段每天最多「巴士數 × 16」人。一輛巴士在路上算 2 輛車。
- **巴士專線**：巴士在那條路上不塞、也不佔車的路；車只剩 6 成路。
- **每年預算 12**：一輛巴士 1、一條專線 3。開通以後每年都可以改線、加減車、開關專線，下一年生效。巴士一開大家就看得到（沒有口耳相傳）；開車的人照樣每年往真的塞車改 0.3，擠也慢慢學（擠多少算多少：超過 1/4 算滿 4 格，避免一開一關來回跳）。
- **分數**：每年「沒有巴士」的塞車 − 你的塞車，八年加起來（沒有巴士時每年 495）。門檻 250 / 500 / 750（`bots/v7_bus.js`，每年同一套方案的局部搜索：最好 829——藍田→觀塘站、藍田→將軍澳兩頭的巴士 + 將藍隧道專線，加順利→秀茂坪站→寶琳；局部最優 p90 約 570、中位約 220）。AI 示範：過關 253、高分 503（只有一條：順利→秀茂坪站接駁東九龍綫 + 秀茂坪道專線）、大師 829。
- **畫面**：同第三關（會動的地圖、頂部大字、按住「👁」看穩定以後 / 沒有巴士）；巴士是一輛輛有顏色的車在路的另一邊走，塞的時候慢；指著站（站工具）、路（專線工具）或「＋/−」，整張地圖變成改了以後的樣子，頂部寫「這一步 → 塞車 ±%、坐巴士 ±人、路上的車 ±%」。

## 統一的版面（v7.11）：模式 2、3、4 都照第一關

發起人說第二到四關「太亂、規則都看不懂」，第一關的版面最舒服——所以模式 2、3、4 改成第一關的骨架，只把各關的內容放進同樣的位置：

- **頂上**：同一條五站導航（`shared/nav.js`，`<nav id="navrow" data-current="N">`）——01 車站與步行 · 02 地鐵 · 03 路會塞 · 04 地面巴士 · 05 沙盤（即將推出），點一下到那一關（打包檔之間互相連）。第一關也換成這一條。
- **左邊**：返回 / 本關 / AI 示範 + 一個標籤 → 模式名、大標題 → 一兩句說明（lede）→ 目標框（分數 / 大師線 + 刻度）→ 控制列（開通或下一年、自動播放、👁 按住、↺）→ 三張卡（第一關是 A/B/C 站；模式 2、3 是「線 / 站 / 列車」；模式 4 是 A/B/C 巴士線）＋ 選中那張的詳情框（同第一關的站框：一行一個數，按鈕和工具在裡面）→ **三條規則**（短）→ 怎麼看（圖例）。完整規則在頂上「Rules」。
- **地圖**：第一關的畫法——點紙、淡色路帶（模式 3、4 塞的路中間一條紅 / 橙線）、樹叢花、水、像素房子；屋苑一圈綠＝坐公共交通的人。左上角「第 N 年」（像第一關的鐘），右上角今年 / 預覽一句話，底下四個大數字（模式 2：坐地鐵 / 走路 / 開車 / 知道新線；模式 3：坐新線 / 坐地鐵 / 開車 / 塞車；模式 4：坐巴士 / 坐地鐵 / 開車 / 塞車）。
- **右邊**：逐年表（像第一關的潮汐表：過去的變淡、下一年灰字預告）、路況（模式 3、4；模式 4 每條路旁邊有「專線」開關）或「大家去哪裡」（模式 2）、調度提示一句話、算式表收起來。
- 預覽（指著站 / 路 / ＋−、按住 👁）只改地圖、右上角那句和底下四個數；左右兩邊的框只跟方案變（框在滑鼠底下重畫會吃掉點擊）。

## 引導提示怎樣加

在模式的 `ui.js` 裡列出「時刻 → 文字」（例如 `TIPS={l1:{start:'tip.start',placed:'tip.placed',full:'tip.full',break:'tip.break'}}`），在那個時刻呼叫 `Tips.fire('placed', 旁邊的元素)`。文字放在 `strings.js`。每條提示每個瀏覽器只出一次；玩家按「不再提示」就全部關掉。

## AI 示範（臨時，之後會刪）

**刪除方法**：刪 `mode1-bus/demo.js`、`mode1-bus/demo-plans.js`；`mode1-bus/index.html` 和 `build.py` 裡標「AI demo」的兩個檔名；`ui.js` 裡標「AI demo」的幾行（`TL_GAME.demo`、frame 裡的 `clamp / tick / onBreak`、`put` 和 `reset` 開頭各一句、`tl:level` 事件）。不刪也不影響遊戲：沒有 `demo.js` 時這些行什麼都不做。

## 第五關的 AI（v7.12 起，2026-10-14）

一句話 → 關卡請求 → 切關卡 → 機器人驗收。AI 只能從菜單選（20 個片區、四種時段、最多 4 條改動：某地住的人 / 崗位 / 路能過的車，各有上下限），其餘都是程式（切關卡見 `docs/for-codex/task-53-level-cutter.md`）。

- **後台**：`backend/feeder_ai.py`（FastAPI，掛在 `backend/main.py`）：`GET /api/feeder/ai/status`、`POST /api/feeder/ai/level`（`{sentence, lang, names?, feedback?}`，不合格自動重問一次；與交通無關或有害的話會拒絕）、`POST /api/feeder/ai/comment`（復盤點評，裡面的數字必須是遊戲給的，程式核對）。錯誤格式 `{message}`，同組員網站的 `/api/game/ai/*`。密鑰只在後台：`.env` 的 `DEEPSEEK_API_KEY`（`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 可選，預設 `deepseek-chat`）。遊戲頁面也從後台的 `/feeder/` 提供，和 AI 同源。
- **頁面**：`ai/client.js`（`TLAI.generate(一句話, {build, names})`：問 AI → 交給切關卡 → 有問題把原因回給 AI 再試一次；沒有後台或沒有密鑰時，用 5 個現成示例按關鍵字對上）、`TLAI.comment(summary)`（AI 不在時用程式寫的一句）。
- **測試**：`uv run pytest backend/test_feeder_ai.py`（16 項，用假回覆、不聯網）；有密鑰後 `uv run python game-feeder/tools/ai-test/run_sentences.py` 跑 30 句固定測試（`ai/test-sentences.json`），記通過率、時延，寫到 `data/cache/ai-test/`。
