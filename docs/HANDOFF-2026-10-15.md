## 三、在新电脑上跑起来
```powershell
git clone <仓库地址> transitlab-hk
cd transitlab-hk
uv sync                                   # Python（后台和工具）
copy .env.example .env                    # 然后由发起人自己填 DEEPSEEK_API_KEY；绝不提交、绝不贴到聊天里
cd frontend; npm ci; npm run build; cd .. # 全港数据地图（可选）
scripts\start-feeder.cmd                  # 启动后台 8000 并打开 http://127.0.0.1:8000/feeder/
```
- 只玩游戏、改游戏，不需要 `.env`（AI 会退回现成示例）。
- 没在 GitHub 上的东西：`.env`（密钥）、`frontend/dist`（上面一条命令构建）、`data/build/basemap/`（全港数据地图的底图 192 MB，没有也能打开，底图会从地政总署取瓦片或空白）。游戏本身不需要它们。
- 离线单文件（`模式N-….html`、`开始.html`、编辑器单文件）由 `python game-feeder/v7/build.py` 生成，改完源码要重跑。

## 五、工作方式（接手后建议）
原来是「Codex 在桌面副本里做、交增量包，Claude 审、真鼠标验收、提交」。新电脑上建议：
1. **一个任务一个分支**：`git switch -c task/NN-简称`，直接在仓库里改（不用再复制到桌面）。任务书里写的 `F:\transitlab-hk`、`%USERPROFILE%\Desktop\TransitLab五模式-Codex\…` 换成本机仓库路径；「项目只读、不做 git、交增量包」那几条在新电脑上改成「只在自己的分支上改」。**白名单（只许改哪些文件）照旧遵守**，这样几个任务同时做也不打架。
2. 做完跑第六节的检查，**真浏览器点一遍**（`tools/browser-tests/` 的脚本或自己写的），截图留证。
3. 合进 `main`：`CHANGELOG.md` 最上面加一条（香港时间、提交编号、改了什么、为什么、怎么验证；格式照现有的），需要时 `game-feeder/LOG.md` 也加；提交说明用中文写清楚；推送后确认本地和 GitHub 一致。
4. 绝不：提交 `.env` 或任何密钥、把密钥打印出来或贴到聊天里、提交 `data/raw/` `data/cache/` `data/snapshots/` 或 > 50 MB 的文件、手改 `data/model/` `data/web/`、反复刷政府的数据接口、自己发布网站或登录账号（这些由发起人做）。
5. 文字三语（繁 / 简 / 英），改完跑 `node game-feeder/tools/check_strings.js`。
