# 四、要产出什么

`data/web/corridor-diagnosis.json`，四个部分：

## 1. `by_station` — 每个能比的计数站一行

| 字段 | 含义 |
|---|---|
| `station`、`link`、`road_type` | 普查站标识 |
| `observed`、`modelled` | 8–9 时**双向**流量（`aadt × 该站逐小时比例[8] / 100`），和模型对应路段方向之和 |
| `ratio`、`geh` | 模型/普查，以及 GEH |
| `by_class` | 一个字典：`car / taxi / goods_light / goods_heavy / coach / bus` 各自的 `{modelled, observed, ratio}`（**只有核心站有 OCC 表才填，否则为 null**） |
| `worst_class` | `by_class` 里偏离 1.0 最远、且观测值 > 50 辆的那个车种名（没有则 null） |

## 2. `by_corridor` — 按走廊汇总

走廊定义**照抄 `27` 里的 `CORRIDORS` 常量**（过海 / 沙田－九龙 / 屯门－荃湾 / 将军澳 / 大屿山），
不要自己重新分组。每条给：站数、观测合计、模型合计、比值、GEH<5 的比例、最偏的那一站。

**另外加一条 `内部分流偏差`**：走廊总量对得上但内部分配错，是这个模型最典型的病。
定义：`Σ|模型_i − 普查_i × (Σ模型/Σ普查)| / Σ普查`——
即先把走廊总量对齐，再看各站还差多少。**这个数比 GEH 更能说明"是不是分流错了"。**

## 3. `by_class` — 全部核心站汇总的车种偏差

每个车种给：模型合计、普查合计、比值、以及**偏差最大的 5 个站**。

## 4. `summary` — 中文结论，每条一句

至少要能自动说出这几句（数字从上面算，**不要写死**）：

- 全网 GEH<5 的比例、走廊 GEH<5 的比例；
- 哪条走廊的**内部分流偏差**最大；
- 哪个车种的偏差最大、它主要偏在哪几个站；
- 按 `road_type` 分组的模型/普查比值（支路偏低是已知的接驳线抽象问题，**要在结论里点明这一点，
  不要把它当成缺陷**，见 handoff 6.56）。

# 五、自查（**验收标准，必须逐条原样实现，不得替换、不得删减**）

| # | 检查什么 | 阈值 |
|---|---|---|
| 1 | 你算的全网 GEH<5 比例，与 `assignment-audit.json` 里 `geh_under_5` | 差 < 2 个百分点 |
| 2 | 你算的走廊 GEH<5 比例，与 `assignment-audit.json` 里 `corridor_geh_under_5` | 差 < 2 个百分点 |
| 3 | 你算的各车种比值，与 `assignment-audit.json` 里 `per_class_ratio` | 每项差 < 5% |
| 4 | `by_station` 的站数 | ≥ 150 |
| 5 | 每个 `by_corridor` 的站数之和 ≤ `by_station` 的站数 | 无例外 |
| 6 | `内部分流偏差` 落在 [0, 2] | 无例外 |

第 1–3 条是**和 `27` 自己的结果交叉验证**：如果你的口径和它不一致，说明有一边错了，
**必须查清楚再交，不要调阈值让它过**。

# 六、这个工程的已知坑

1. **一个普查站可能对应多条并行车道**（`census-links.parquet` 里同一个 station+direction 有多行），
   必须求和，不能取第一条。这个坑已经踩过一次（东隧只数了一条管道）。
2. **普查的 `am_peak_flow` 是该站自己的高峰小时**，不一定是 8–9 时。
   所以第 1 部分要用 `aadt × 逐小时比例[8]`，**不要用 `am_peak_flow`**。
   `27` 的全网 GEH 只挑"高峰恰好是 8–9 时"的方向来比，**这是两个不同的口径**，
   第 1 条自查对比时要注意用同一个口径（跟着 `27` 走）。
3. **OCC 表只有 07:00–23:00 共 16 个时段**，而且只有约 114 个核心站有。
4. 模型的 `bus` 是预载（`preload` 列），不是分配出来的车种。
5. 车种对应关系照抄 `27` 的 `classes` 字典，不要自己映射。
