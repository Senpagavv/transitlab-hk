# 任务

为一个已经写好的香港交通模型工程（`F:\transitlab-hk`），制作一份**极其详尽的"从零到全流程"数据流程图与节点明细**。读者是这个项目的发起人：土木工程背景、非计算机专业，他要通过你的产出完全掌握这个工程每一步在做什么、数据从哪来、公式是什么、怎么验证的。

# 一、安全约束（最高优先级，违反即失败）

1. **`F:\transitlab-hk` 下的任何文件都不得修改、删除、重命名、移动、格式化。** 只能读。
2. **不得运行 `pipeline/` 下的任何脚本**——它们会覆盖数据产出。也不要运行 `audit.py`。
3. 不得执行任何 git 写操作（commit、checkout、reset、clean、stash）。`git log`、`git status` 这类只读命令可以。
4. **不要打开二进制文件**（`.parquet`、`.npz`、`.pbf`、`.zip`、`.gdb`、`.pdf`、`.xls`）。它们的字段和形状已经整理在 `docs/for-codex/data-schemas.md`。
5. **只允许在一个目录里写文件**：`%USERPROFILE%\Desktop\TransitLab流程图\`（不存在就创建）。除此之外不写任何文件，不建临时文件到项目内。
6. 不需要联网。所有信息都在仓库里。

# 四、图的技术要求

- 用 Mermaid（`flowchart TD` 或 `LR`），按阶段用 `subgraph` 分组；
- **节点形状区分类型**：原始数据用圆柱 `[(...)]`、脚本用矩形 `[...]`、中间产物用平行四边形 `[/.../]`、校核用菱形 `{...}`、外部官方数据用虚线样式；
- **边上要标注传递的是什么**，例如 `-->|455 分区 × 7 目的 OD 矩阵|`；
- 用 `classDef` 上色：已完成绿色、未达标黄色、未开始灰色；
- **节点 id 用英文，标签用中文**；标签里有括号、逗号、冒号时必须用双引号包起来，否则 Mermaid 渲染会失败；
- 每张图下面配一段文字说明，讲清楚这张图在讲什么。

# 五、准确性要求（非常重要）

1. **所有数字、公式、参数值必须来自仓库文件**，禁止用常识或经验补充；
2. 每个公式、每个参数值后面标注来源，格式 `pipeline/22_trip_distribution.py:123`；
3. 代码里没有、但你根据上下文推断出来的，必须标 `【推断】` 并说明依据；
4. 全部用中文写作（专业术语可附英文），文件路径保持原样；
5. 遇到脚本说明与代码不一致的地方，**以代码为准，并单独列出这些不一致**，写在 `10_节点明细.md` 末尾的「发现的不一致」一节。
