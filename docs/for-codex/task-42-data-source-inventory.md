# 任务 42：数据来源总目录（初稿）

## 一、背景
TransitLab HK 是香港交通 + 土地的四阶段模型（项目在 `F:\transitlab-hk`）。发起人要一份**数据来源总目录**：
从前到后像一本书的目录，读完就知道模型用了哪些数据、每份从哪来、有多少条、每条包含什么信息。
**不需要**把数据明细抄出来，只要清单和概况。读者是非计算机背景的队友，全文用中文，术语第一次出现时加一句白话解释。

## 二、硬规矩（违反任何一条都作废）
1. **项目只读**：`F:\transitlab-hk` 里一个字节都不许写、不许改、不许删，不许建临时文件。另一个 AI 正在跑模型。
2. **不许运行 `pipeline/` 下的任何脚本**，不许访问任何网络接口（政府服务器会封 IP）。
3. **只允许写一个目录**：`%USERPROFILE%\Desktop\TransitLab数据来源\`（不存在就创建）。
4. 读大文件只读元数据/条数（parquet 用 `pyarrow.parquet.read_metadata`；geojson/json 读结构；
   `.gdb.zip` 用 `pyogrio.read_info`，读之前先设环境变量 `CPL_TMPDIR=F:/tools/gdal-tmp`）。
   Python 用项目的 `F:\transitlab-hk\.venv\Scripts\python.exe`，脚本放在你自己的输出目录里跑。

## 三、去哪里找
- 每个 `pipeline/NN_*.py` 文件开头的说明（docstring）都写了 `Input:`（读什么）和 `Output:`（产出什么），多数还写了数据出处和网址。**这是主线索。**
- `docs/for-codex/pipeline-manifest.md`：每一步的输入输出总表。
- `docs/reuse-and-references.md`：外部数据和许可证。
- `data/raw/`（原始下载）、`data/model/`（模型推算结果）、`data/web/`（网页用数据和各步的 `*-audit.json` 审计报告，审计报告里常有条数和核对结果）。
- `docs/handoff.md` 第 5 节左右有数据全表，可参考但以代码和文件为准。

## 四、要产出的文件：`数据来源总目录.md`
### 结构
0. **一页总览**：一张表列出全部来源（编号、名称、发布机构、年份、类别、实测/推算），按下面的类别排序。
1. 按类别分章：
   A 人口与住户（人口普查 / 中期人口统计、规划署人口分布推算、统计处表格）
   B 土地与规划（土地用途格网、法定图则、地价）
   C 建筑物与设施（地政总署建筑物、屋宇署用途、学校、医院、院校）
   D 道路网（运输署路网中心线及其各图层、OpenStreetMap 车道）
   E 公共交通（运输署 GTFS、社区版 GTFS、港铁车费、班距）
   F 出行调查与行为参数（2022 年出行特征调查、2011 年货车调查、运输规划及设计手册 TPDM）
   G 交通计数与实测（年度交通普查、道路探测器、交通月报）
   H 跨境（入境处出入境人次、教育局跨境学童、运输署跨境车辆）
   I 价格与收费（隧道费、的士收费、车费表）
   J 底图与地名（地政总署底图、地名）
   K **模型推算出来的数据**（`data/model/` 里的主要文件：出行端点、时间矩阵、出行分布、方式划分、早高峰、分配结果等）——
     这些不是下载的，要写清楚「由哪几份来源、经哪一步推算出来」
2. **每个来源一小节**，固定格式：

| 项 | 内容 |
|---|---|
| 名称 / 发布机构 / 年份或版本 | |
| 网址（代码里写了才填，别编） | |
| 本地文件 | 路径、格式、大小 |
| 规模 | 多少条 / 多少个区 / 多少个站 / 覆盖哪些年份（从文件读出来的真实数字） |
| 每条包含什么 | 主要字段 + 一句白话（例：`am_peak_flow` = 早高峰那一小时这个方向过了多少辆车） |
| 空间单位 | 如 211 个普查小区 / 455 个交通分区 / 36,471 条路段 / 807 个探测器 |
| 实测还是推算 | 实测（官方数字）/ 推算（模型算的）/ 估算（假设），推算的写出依据 |
| 用在哪一步 | 读它的 `pipeline/NN_*.py` |
| 已知问题 | 代码或审计里写到的坑（例：探测器车流 9/26 前多算一倍，已修） |

3. 结尾一张「**模型最终用了什么**」的表：按四阶段（出行生成 → 分布 → 方式 → 分配）列出每一阶段直接读的数据。

### 质量要求
- 所有数字必须是**你从文件里读出来的**，或者代码/审计里明确写着的；读不到就写「未核实」，**绝不编数字、编网址**。
- 附一个 `核对记录.md`：列出每个数字是从哪个文件、用什么方法读出来的，方便复查。
- 写完自查一遍：`data/raw/` 下每个子目录、`data/model/` 下每个主要文件，都应在目录里出现（或说明为什么不列）。

## 五、完成后
在输出目录里放 `数据来源总目录.md` 和 `核对记录.md`，回复一句话告诉发起人写好了、共多少个来源、有几处「未核实」。
