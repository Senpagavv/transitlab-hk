## 三、规则（引擎）：「以模型为基准，只算改动带来的差」
这是 `game/engine`（修地铁 demo）已经用的做法，好处是**什么都不建＝模型原样，天然稳定**。规则仍然「按格子数」，和前四关一样好讲：

- **单位**：分区（455 个）是出发和到达的单位，人在分区的代表格（`zones[].cell`）。1 格 400 米；**1 格＝2.5 分钟**（走路每格算 2 格＝5 分钟，同第二关）。
- **基准**（来自 `hk-demand-<period>.json` 的 `pairs`）：每对分区的开车人数 `car0`、坐公交人数 `pt0`、开车分钟 `carMin`、公交分钟 `ptMin` → 换成格数 `car0b = carMin/2.5`、`pt0b = ptMin/2.5`。路段基准负荷 `load0`、容量 `cap`。
- **玩家能做**（第一版）：画一条或几条新地铁线（4 连通格子，可拐弯不分叉）、放站、列车数；预算按全港放大（起点：线每格 1、站 3、列车 4、预算 300，可调）。新站离老站 ≤ 1 格＝可换乘（走路 + 等车）。
- **新线让公交快多少**：港铁网（老线 + 新线）上算每对分区的地铁格数（走到站每格 2、等车 2、每站一格、换乘＝走路 + 等车、走出站每格 2；走到站最多 6 格）。`d = max(0, 没新线时的地铁格数 − 有新线时的地铁格数)`（没新线时走不到地铁，就用 `pt0b`）。公交格数 `ptb = pt0b − d`。
- **路通了开车快多少**：每段路多出来的格数 `extra = (load ÷ cap)²`（同第三关）；开车的人按「以为的」塞车算，每轮往真的塞车改 0.3（同第三关）。`c = Σ沿路（以为的 extra0 − 以为的 extra）`（路变通为正）。
- **换不换**（第二关的「省几格几成」，写成差值）：开车的比例 `carShare = clamp(car0/(car0+pt0) − 0.1 × (d − c), 0, 1)`；人数总量先不变（「顺路 / 多出门」第二版再加）。
- **路**：每对分区的开车路线＝格子路网上的最短路（第一版固定，按基准塞车定）；`load = load0 + Σ（开车人数变化 ÷ 每车 1.3 人）` 沿路累加。
- **地铁挤**（第二版）：每段 `perHour > cap` → 下一轮经过这段多 4 格（同第二关），也慢慢学。
- **一轮**：按「以为的」算换不换 → 路上加减车 → 新的塞车 → 「以为的」改 0.3。连跑到稳定（最后 5 轮总开车人数变化 < 0.5%）。
- **看什么**：坐新线的人 / 小时、少了多少车、全港塞车（Σ 车 × extra）比基准少多少、省下多少人·分钟；每个分区开车比例的变化。
