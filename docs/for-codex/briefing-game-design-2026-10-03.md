# 给 Codex 的简报：TransitLab 游戏玩法讨论到哪了（2026-10-03）

> 用途：发起人想和你（Codex）一起聊游戏玩法，请你先读完这份简报再给意见。这不是任务书，没有固定产出；如果你要动手做小样，规矩见第九节。
> *English abstract: TransitLab HK is a Hong Kong transport model for a student hackathon (Green Transport & Smart Mobility). We are trying to turn it into a fun, simple game that helps the public understand transport-planning decisions. Several game designs have been built and rejected by the project lead. No single mechanic is fun yet. The lead wants to find ONE core interaction that is fun on its own, then stack features one at a time, each tested before the next. This brief lists what was tried, why it failed, the lead's principles, the assets available, and the open questions.*

## 一、背景
- 项目：TransitLab HK（`F:\transitlab-hk`，GitHub 私有仓库 Senpagavv/transitlab-hk）。发起人：城大土木硕士，交通规划方向，**不是计算机专业**；用中文沟通，喜欢简单直白、带土木 / 交通工程类比。
- 比赛：Hack for SDGs 2026（跨校生成式 AI 黑客松），**绿色交通与智能出行**赛道。评分五项各 20%：问题定位、原型、生成式 AI 用得是否恰当、可行性与影响、可持续与伦理。
- 时间：中期报告 10/4 23:59 截止；**10/18 交路演稿 + 原型**；10/22 每赛道选 10 队；10/24 决赛（城大）。
- 底层已有一个校准过的**全港四阶段交通模型**（2026 年基准：455 个交通分区、出行生成 → 分布（重力模型）→ 方式选择（多项 logit）→ 分配（路网 BPR 拥堵、港铁 / 公交），审计 118/120 项通过，数据分 A 实测 / B 校准推算 / C 依据推断 / D 示意假设 四级）。

## 二、我们想做的游戏（目标，没变过）
1. **让普通市民理解交通规划的决策**：为什么要这样修、这样修会牵动什么。核心概念是 TOD 和重力模型——发起人认可的简化说法是**引力**（地方吸引人 / 出发地推人）、**阻力**（整趟出行有多难，人越多越堵、阻力越大）、**选择**（去哪、怎么去、走哪条路）。
2. **好玩**：有目标、有反馈、能发挥"小聪明"，玩几局能摸到规律。
3. **贴赛道**：绿色（把人从私家车 / 的士接到公共交通、少排碳）和智能出行（调度、诱导、专线等）。
4. **真实数据是地基，但不能成为玩家的负担**；为了好玩，数字可以夸张。

## 三、发起人的原则（请严格遵守，他反复强调过）
1. **一步一步叠加**：先找到**一个本身就好玩的功能**，玩明白、确认好玩，再加下一个。现在**连一个好玩的功能都还没有**。
2. **简单到能心算**：一个决定会影响什么，玩家要事先能想清楚、事后能看清楚，而且在时间上要有明显改观。
3. 每加一层规模或规则，**系数和规则必须固定**，不能是连设计者都算不出来的东西。
4. **地图要一眼看懂**：不要让玩家自己开图层开关；不要乱；能看出"这部分车 / 人是从哪来的、在哪下手能减堵"。
5. **不要**：一步一步指着做的"连线游戏"式指引；强制暂停；卡牌决策类（像《王权》那种留给以后的政策沙盘，不做主玩法）；"遗产结算"这种让玩家同时想两件事的设计。
6. 视觉美术以后有人做；现在要先把**玩法和后端**做对（后端要能给任何前端用）。
7. 讨论阶段**先口头聊清楚再做**，不要做一堆用不上的东西。

## 四、试过的方案和被否决的原因（按时间）
| # | 方案 | 发起人的反馈 / 否决原因 |
|---|---|---|
| 1 | **修地铁 v1**（`game/`、`game-ui/` 首页的自由世界）：在真实地图上点站连线，跑完整四阶段模型 4 轮（约 25 秒），出账本（客流、省时、碳、造价、40 年净收益） | 画几条线、等结果、一张报表就结束，没有反馈，不好玩 |
| 2 | **出题模式 v2**：数据自动出题（通勤题 / 打败政府规划线 / 发展题）、"规划顾问"分 8 步打分、每点一站 0.1 秒快算跳数字、列车动画、市民说话、通车日和政府方案对比 | 看不到人口等数据（要自己开图层）；指引太细像连线游戏；目标和玩法开场没讲清 |
| 3 | 讨论：**大事件 + 限时**（外星人降临启德发礼物、吸血鬼疏散等夸张事件） | 方向被接受（夸张事件有吸引力，结尾彩蛋揭晓"其实是演唱会散场"） |
| 4 | 讨论：**"想法"抽象**（一群人 A→B、多少人、开不开心）+ Codex 做的想法地图（43 个生活圈、80 个想法、热点段） | 思路被接受；但发现平时香港 80 个想法里 70 个是满足的，问题要靠事件"冒出来" |
| 5 | 讨论：卡牌决策（《王权》式四个数值平衡） | **否决**：离 TOD 太远，变成决策卡牌游戏 |
| 6 | 讨论：节奏——波次（像塔防）→ 日夜节奏 → 回到"3 小时就是 3 小时" | 波次在现实里讲不通；日夜节奏冲淡了目标；遗产结算否决 |
| 7 | 讨论：修地铁 → **派巴士**（散场不会修地铁）；分 10 个片区 → **不分片区**（直接用细的人口出发）；干道简化成 13 条（后来 20 条） | 接受 |
| 8 | **外星人 demo v1**（`game-ui/alien/`）：实时 3 小时；人在家决定去不去（太慢就放弃）和怎么去；干道是排队模型；工具＝巴士上车点 + 巴士专线；堵了自动暂停 | 完全看不懂怎么玩；主干道太少；点了没什么可操作；强制暂停很烦；车点和底图对不上 |
| 9 | **外星人 demo v2**：只留巴士专线（≤4 条）+ **鼠标停在干道上预演**（重放模拟，显示各路变顺 / 变堵、多送多少人）；20 条干道沿真实道路；加公共巴士；不强制暂停 | **还是很奇怪**：后期中间全堵死，玩家的动作对整体太小；时间紧；看不出车从哪来、在哪放能减堵；可关联的点太多，想不过来；无聊 |
| 10 | Claude 提议：小地图 + 按小时一回合 + 固定系数 + 一关加一样东西 | 发起人："不是这个意思"——他要的是我们一起**一个功能一个功能地试玩、确认好玩再叠加**，而不是先设计一整套关卡 |

## 五、现在的位置（结论）
- 还**没有一个本身好玩的核心操作**。下一步是找到它：一个动作，效果清楚、可预测、在时间上看得见、能让玩家动脑，又和 TOD / 重力模型沾边。
- 找到之后再一层层加：人群、路、港铁、放弃（重力模型）、站旁开发（TOD）、大事件……每一层都先试玩。

## 六、讨论里暴露的关键难点（请重点帮忙想）
1. 真实的交通系统维度太高（几百个出发地、几十条路、人会改主意），**人凭直觉看不出规律**。怎样把它压成少量看得懂、能推理的元素？
2. **一个动作的效果要可预测、可见、在时间上显著**。现在的问题是：大事件后期全堵，一个动作杯水车薪。
3. **归因**："这些车是从哪来的、该在哪下手"——要一眼看出。
4. **交叉影响要有、但要能理解**：两三个因素可以，多了就想不过来、变无聊。
5. 实时还是回合？发起人想要一点时间压力，但不想手忙脚乱；可以暂停思考。
6. 怎样在游戏里体现"引力 / 阻力 / 选择"、TOD、绿色出行，又不变成上课。

## 十、术语
- **想法**：一群人从 A 去 B、多少人、现在开不开心（满足 / 太慢 / 太挤 / 断了）。
- **引力 / 阻力 / 选择**：重力模型的白话版。引力＝地方吸引人（岗位、活动），出发地人多推力大；阻力＝整趟出行有多难（时间、等车、换乘、堵车、车费），人越多阻力越大；选择＝去哪、怎么去、走哪条路。
- **干道 / 专线**：外星人 demo 里简化后的 20 条主干道；巴士专线＝一条车道只给巴士用（巴士不堵，私家车少一条车道）。
- **快算 / 完整模型**：0.03 秒只算新线客流 / 25 秒跑完四阶段 4 轮（含方式和去向变化、路网拥堵）。
- **A / B / C / D**：数据可信度——实测 / 校准推算 / 依据推断 / 示意假设。
