# 二、唯一要改的算法：逐小时曲线改用普查实测

## 第 1 步：算出普查的的士逐小时人次形状

数据在两个文件里，**注意两者的小时覆盖不同**：

| 要什么 | 从哪读 | 覆盖 |
|---|---|---|
| 每站每小时占全日车流的比例 | `data/web/traffic/atc-stations.json` → `hourly[]`，取 `year == 2024`，字段 `weekday_pct`（长度 24，单位 %） | **24 小时齐全** |
| 每站每时段"的士占车流的比例"与"每辆的士的人数" | `data/web/traffic/atc-occupancy.json` → `stations[]`，取 `year == 2024`，`hours` 字典，键形如 `"0800-0900"`，里面 `taxi.share_pct` 与 `taxi.occupancy` | **只有 `0700-0800` 到 `2200-2300` 共 16 个时段**（另有一个 `"16 hours"` 汇总键，**不要用**） |
| 每站全日车流 | `atc-stations.json` → `records[]`，取 `year == 2024`，字段 `aadt`（按站把两个方向求和） | — |

算法：

```
flow[h]  = Σ_站 ( aadt[站] × weekday_pct[站][h] / 100 )              # h = 0..23
share[h] = 按 aadt×weekday_pct 加权的 taxi.share_pct 平均值 / 100
occ[h]   = 同样加权的 taxi.occupancy 平均值
person[h] = flow[h] × share[h] × occ[h]
census_hour[h] = person[h] / Σ_h person[h]
```

**缺失时段的处理（必须照做，不得自行发挥）**：`share[h]` 和 `occ[h]` 在 00:00–06:00 用 `0700-0800`
时段的值，23:00 用 `2200-2300` 时段的值。在中文报告里明确写出这是假设，并写明受影响的 8 个小时。

**必须在报告里写明的口径说明**（原样写出，不要改写）：
> `flow × share × occ` 是"经过普查站的的士乘客人次流"，严格说正比于**人公里**而不是**人次**；
> 若各小时的平均行程长度不同会有偏差。这里作为时段形状使用，其准确性由第 3、5 两项自查约束。

## 第 2 步：把每个目的的小时矩阵按这个形状重标定

```
tcs_hour[h]    = Σ_目的 ( 该目的全日的士人次 × hourly_profile_pct[目的][h] / 100 )
k[h]           = census_hour[h] × Σ_h tcs_hour[h] / tcs_hour[h]
P[目的][h]     = P[目的][h] × k[h]
```

即：**只改各小时的总量，不改同一小时内各目的的相对构成**（这和 `pipeline/24_peak_hour.py`
对私家车/的士/校巴做的事完全一样：按普查改高峰比例，总量守恒）。
`tcs_hour[h]` 为 0 的小时令 `k[h] = 0` 并计数报告。

跨境三个目的（CBS/CBR/CBV）仍按上次的办法借用曲线，重标定对它们一并生效。
