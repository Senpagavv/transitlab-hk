## 二、硬规矩（违反任何一条都作废）
1. **项目只读**：`F:\transitlab-hk` 里不写、不改、不删任何文件，不建临时文件；**不运行 `pipeline/` 下任何脚本**（会改写正式数据，部分要跑 10 分钟以上）。
2. **不访问任何网络接口**。
3. **只允许写一个目录**：`%USERPROFILE%\Desktop\TransitLab推算方法\`（不存在就创建）。需要写小脚本读数据时，脚本也放这里，用 `F:\transitlab-hk\.venv\Scripts\python.exe` 跑，**只读**打开项目文件。

## 四、工作流程（按顺序，每一阶段先产出再进入下一阶段）

### 阶段 2　逐步写方法卡（主体）
每个有计算的步骤一张「方法卡」，**固定格式**：

1. **这一步在四阶段里的位置**（一句话 + 上游读什么、下游给谁）。
2. **方程**：用 Markdown 数学公式（`$...$`、`$$...$$`，GitHub 和 VS Code 都能显示），每个方程下面：
   - 每个符号的含义和**单位**；
   - **白话解释**（一两句，给土木背景的人：可以用"就像……"的类比）；
   - **代码出处** `pipeline/xx.py:行号`；
   - **本模型的取值**（从代码或审计报告读出，写出处）。
3. **拟合 / 校准**（有才写）：
   - 对准什么观测数据（哪个表、哪份调查、多少个观测点）；
   - 调哪些参数、目标函数是什么（例：加权最小二乘、平均出行时间相等、份额相等）；
   - 用什么算法（二分法、黄金分割搜索、Furness 配平、逐次平均 MSA、对数比更新、Frank-Wolfe 类均衡算法……）和**停止条件**；
   - 实际跑了几轮、最后误差多少（从审计报告读）。
4. **核对**：审计里拿什么官方数字对账、现在对上多少（如 GEH、模型/普查比值）。
5. **已知局限**（代码、handoff 里写明的）。
