2. **道路菜单与范围**：菜单改为 `{片区: {places: [...], roads: [...]}}`；屋苑／分区与道路分开。`ai-level.js` 只新增读取底板并传菜单的逻辑。道路取自框内保留候选路段对应的 `roads`，用已有中文名和既有双语别名，排除未命名道路。后台 `road_cap.place` 必须在道路菜单中；旧数组仍支持人口／岗位。切片器要求中英道路名精确匹配，匹配后对同名道路全部段生效。容量范围统一 **−60%～+50%**，人口／岗位仍为 −50%～+150%。
3. **地点别名**：后台集中维护启德（含啟／啓）、启德体育园／邮轮码头、第一城、逸东、东涌东、洪水桥、北都。启德普通叫法固定 `啓德站一帶 / kai-tak`；明说九龙东可用 `kowloon-east`，仍不能换九龙湾。第一城固定 `第一城站一帶 / sha-tin-tai-wai`。

## 已知边界，交给 Claude 时保留

- **北都缺数据**：当前 `northern-metropolis` 框内没有分区；底板古洞格 `[71,17]` 在北都框外，也在粉岭上水框左侧一格外。底板没有独立“新田”分区，不能把沙田“新田圍邨”当成它。后台明确给 `area_empty` 并提示改用新田／古洞所在片区、先补框。两句测试的期望是“正确提示缺数据”，玩法／片区／改动分母不计这两句；不是已经生成可玩关卡。未越界修改片区或底板。
- **中文道路覆盖有限**：全港底板仍有 234 种仅英文且没有现成双语别名的道路名（按名称去重）。本次只使用底板中文和 `cut.js` 已有别名，没有猜译或改数据；这些道路不进入中文菜单。若还要红隧等未中文化道路，需按正式双语来源补底板或别名后再验收。
- `validate()` 是保守的文字线索检查，不是完整语义解析。细微否定、跨区迁移、同类地点多加数量等仍需看 60 句真 AI 分数和原始回复；不能宣称完全防止所有幻觉。
- 模糊规模的 `pct_range` 是测试约定，不是实测数据；新入伙但未给人数时，故事应明确是假设。现成离线示例只支持有限固定场景，不等于自由文本理解。
- 评分器能检查标题长度，不能自动判断“將隧封線早高峰”这种措辞是否别扭。时段、整关可达性、难度和机器人验收仍依赖原有生成器，`simplify.js`、`generate.js` 留给任务 64。
