# 任务 48：「想法地图」——把全港出行翻译成几十个简单的「想法」

## 一、背景
修地铁游戏要换一种思维（发起人 2026-10-02 定）：**交通网络依旧复杂，但每个人的想法很简单**——「一群人，从 A 去 B，有多少人，现在开不开心」。
玩家只看这些「想法」：哪些被满足、哪些没有、为什么没有（太慢 / 太挤）；修线去满足它们——直接牵线、或者分流减压（帮爆满的一段卸压，经过那段的想法都跟着变开心）、或者接驳到有空位的线。
**这个玩法成不成立，取决于第一步：真实数据翻译成「想法」之后，人能不能一眼看出规律。** 你要做的就是这一步，并做一张能看的地图页。

## 二、硬规矩（违反作废）
1. **项目只读**：`F:\transitlab-hk` 不写、不改、不删（可以读、可以 import 运行；不要运行 `pipeline/` 里的脚本）。
2. **只写一个目录**：`%USERPROFILE%\Desktop\TransitLab想法地图\`（脚本也放这里）。
3. **不联网取数据**（底图瓦片可以，见下）；**不编造**：每个数字从项目数据算出来；做不到的写「做不到 / 缺什么」。
4. 阈值（多慢算慢、多挤算挤）都写在 `说明.md` 里，并说明为什么这样取。

## 四、要做的 6 步
1. **划生活圈**：把 455 个分区合成 **35–45 个生活圈**——同一区内、地理上连在一起；新市镇单独成圈（天水围、屯门市中心、元朗市、将军澳南 / 北、东涌、沙田市中心、马鞍山、大埔、上水粉岭……），主要就业中心单独成圈（中环金钟、尖沙咀、旺角、观塘商贸区、九龙湾……）；名字要是普通人一看就懂的地名。
2. **抽想法**：生活圈→生活圈的早高峰坐公交人数；同圈内部不算；只留够大的（建议 ≥ 2,000 人 / 小时，自己调到 **40–80 个想法、覆盖跨圈公交出行的一半以上**，写明覆盖了多少）。每个想法记：起、终、人数、坐公交平均分钟、开车平均分钟（人数加权）。
3. **现在走哪条路**：用港铁站序搭一个只有港铁的简化网（站间时间可用 GTFS 时刻或距离 / 速度估），起终点走路或坐巴士到最近的站（写清怎么估），找每个想法现在最可能走的港铁路线，记下经过哪几段、哪个换乘站。没有合理港铁路线的（例如一直靠巴士）也要标出来。
4. **为什么不开心**：
   - 🧱 **太挤**：路线经过的段里，最挤一段的载客率 > 1.0（用 transit-assignment 的 `load_factor`）；记下是哪一段。
   - 🐢 **太慢**：坐公交比开车慢很多，且绝对时间长（阈值你定，例如 > 开车的 2 倍且 > 45 分钟）。
   - 😊 其余算满足。
5. **热点段**：每一段港铁有多少个想法、多少人经过；载客率 > 0.9 的段按「经过的想法数」排序——这就是「修一条分流线能救一片」的地方。
6. **地图页**（双击打开的单个 HTML，数据放同目录 `.js`；地图库用 `F:\transitlab-hk\game-ui\vendor\leaflet.js` 复制过去，底图可用 `https://mapapi.geodata.gov.hk/gs/api/v1.0.0/xyz/basemap/WGS84/{z}/{x}/{y}.png`）：
   - 生活圈：圆或淡色区块（大小 = 人口），写名字；
   - 想法：从起点圈到终点圈的弧线箭头，粗细 = 人数，箭头中间一个表情 😊 / 🐢 / 🧱 和人数；
   - 现有港铁线：按载客率着色（绿 / 黄 / 红），红色热点段旁边写「N 个想法经过」；
   - 点一个想法：高亮它现在走的路线和卡住的那一段，侧栏说明「天水围→观塘 1.2 万人，现在 72 分钟，要经过 东铁 大围→九龙塘（137%）」；
   - 右侧列表：想法按人数排序，可按状态筛选；
   - **不按任何开关就能看懂**；图例写清楚；放大缩小都不能乱成一团（想法多时缩小只显示前 20 个）。
