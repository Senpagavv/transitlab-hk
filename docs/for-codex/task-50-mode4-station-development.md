## 三、规则（复制 `mode2-metro` → `mode4-tod`，在第二关引擎上加）
第二关的全部规则不变：去哪（拉力＝吸引力 − 格数）、怎么去（省几格几成坐地铁）、只有知道的人用新线、口耳相传、挤（明年多 4 格）、顺路再去、走路；预算 40；**线一次建好，开通后不能改线、不能加车**。

地图沿用第二关的新界西北（发起人熟），改两处：
- 洪水橋新發展區一开始还是空地：`attraction` 22 → 10（只有少量工作）。
- 加 `land`：约 16 格空地，摆在洪水橋一带（大约 x 5–9、y 1–4）、元朗西边（x 11–12、y 3–5）、天水圍北（x 3–4、y 3–4）。具体格子你按地图摆，不压屋苑、去处、水；写进 `data.js` 注释。

新规则（就三条，界面上也这样写）：
1. **站旁空地**：车站周围一圈（8 格）里的空地才能卖。第 0 年（开通前）起，每年（每按一次「下一年」之前）最多卖 2 块；按了「下一年」就定下，不能收回。
2. **卖成什么**（下一年起生效）：
   - 🏠 **住宅**：这块地多一个小屋苑，每天 16 人出门（`homePeople`）；他们**都知道新线**（知晓＝1，就是冲着车站买的），照第二关的规则选去哪、怎么去。
   - 🏬 **商业**：这个车站多一个去处「X 站商场」——同一个站的商业地合成一个去处，吸引力＝4 + 6 × 块数（`shopBase` / `shopPer`），开车泊车难（`carExtra` 5），也参与「顺路再去」。
3. **地价**（卖的那一刻按当前情况算，一次性进账）：
   - 住宅价＝`homeRate` × Σ各去处 max(0, 吸引力 − 从这块地去那里最快的格数)（最快＝开车 / 走路 / 坐地铁取最小，当他知道新线）→「住这里，去各处有多方便」。
   - 商业价＝`shopRate` × （加了这块之后每天来这个站商场的人 − 加之前）→「每天多多少人来」。人数用当前的知晓（知道的人才会坐地铁来）。
   - 起点 `homeRate` 1、`shopRate` 0.5，请用机器人调。

**分数＝港铁的账＝Σ 每年每天坐地铁的人（车费，同第二关的分数）+ Σ 卖地收入。**

**调参目标**（机器人证明，写进说明）：
- 好的混合（住宅 + 商业）明显好过全卖住宅、全卖商业（各高 ≥ 10%）。
- 越晚卖地价越高（口耳相传、周围发展起来），但晚卖少几年车费和人流——最好方案既不是「全部第 0 年卖」，也不是「全部最后几年卖」。
- 同一个站住宅卖太多会挤（第二关的挤规则）——列车数要在第 0 年想好。
- 站放在空地旁边 vs 放在老屋苑门口，要有取舍（只修线不卖地的最好方案 ≠ 卖地的最好方案的线）。
