# 任务 66：收组员关卡的工具（一条命令：检查、定门槛、做示范、出报告）

> 分工：Codex 做，Claude 用它收组员关卡、最后验收。10/17 组员交关卡前要。

## 一、要的是什么
组员用编辑器（`v7/editor/`，第一关 `v7/mode1-bus/editor.html`）导出 `tl-level/1` 的 `.json`，压成 zip 发来。要一个工具，Claude 跑一条命令就能：
```
node game-feeder/tools/levels/intake.js <组员的 zip 或文件夹> --out <输出文件夹>
```
输出文件夹里是**处理好的关卡文件**（可以直接放进 `v7/levels/mN/`）和一份**报告**。工具本身**不写进 `v7/levels/`**，由 Claude 看过报告再放。

## 二、硬规矩
1. 项目只读，不做 git。复制到 `%USERPROFILE%\Desktop\TransitLab五模式-Codex\任务66\`，交回增量包。
2. 只许新建 / 改：`game-feeder/tools/levels/**`、`game-feeder/bots/**`（只为让机器人能吃任意关卡文件）、`v7/mode1-bus/demo.js`（见第 3 条，只改取方案那几行）。不改规则引擎、`data.js`、现有关卡。
3. zip 来自组员，当作**不可信输入**：只读 `.json`；路径穿越（`../`）、超大文件（> 2 MB）、非 JSON 一律拒绝并写进报告；不执行里面任何东西。

## 三、做什么
1. **检查**：每个文件跑 `tools/levels/levels.js check` 的同一套检查；`format`、`mode`、必填字段；编号格式；**和现有关卡（`levels/registry.js`）或同批其他文件编号重复**要标出（是「取代」还是撞号，让 Claude 决定）；标题三语缺的列出来（不自动翻译）；`hub.station` 在 `hub/stations.js` 里找不到也标出。
2. **定门槛**：按玩法调完整机器人（第一关 `bots/v7_bus.js`，第二关 `v7_metro_grow.js`，第三关 `v7_roads.js`，第四关 `v7_tod.js` 或任务 64 的加强版若已在项目里），用 `--level` 方式（参考 `bots/v7_levels_batch.js` 里对 `D.example` 的适配），门槛 = 最好 × (0.40, 0.65, 0.88) 取整；同时记下组员自己填的门槛做对比。
3. **AI 示范**：非挑战关做过关 / 高分 / 大师三套，写进 `level.demo`（第二到四关的格式同任务 57）。**第一关**的 `demo.js` 现在只读内置的 `demo-plans.js`，要加上「没有就读 `D.demo`」的回退（同任务 57 对第二到四关的改法），并确定第一关 `level.demo` 的格式、写进说明。每套示范逐操作重放核对分数。
4. **报告** `报告.md`：每关一行（文件名、玩法、编号、标题、作者、屋苑 / 去处 / 路 / 空地数、机器人最好、新门槛 vs 组员门槛、示范分、问题），太容易（最简单方案就到大师）、太难（最好 < 50）、编号冲突的放最前面。
5. **自测**：用编辑器（或脚本）每个玩法做 2 个关卡、故意做 3 个坏文件（坏 JSON、编号重复、路径穿越的 zip），跑通给报告。

## 四、交回
`任务66\说明.md`：用法、自测结果、第一关示范格式、已知局限。附增量包。
